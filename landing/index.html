💰 Cost-Weighted Decision Making

The threshold is not a default. It is the mathematically optimal point where total expected business loss is minimised.

False Positive
₹ 500
Filing a weak dispute defense that loses. Assumed cost: wasted ops time + risk of hurting the merchant's dispute win-ratio with the acquirer.

* Stated assumption, not Razorpay-sourced data.
False Negative
₹ Amt + 1,500
Missing a winnable dispute. Cost: the full transaction amount lost, plus assumed Visa/MC chargeback fee. FN cost ≫ FP cost — so the threshold is intentionally recall-biased at 0.29.

* Stated assumption, not Razorpay-sourced data.

🔒 Defense-Only Architecture

Three independent layers ensure the system can never be repurposed offensively or generate fabricated evidence claims.

# The DefensePacket — every assertion is Optional[bool], never forced to False class DefensePacket(BaseModel): is_defensible: bool compelling_evidence_category: Literal["Proof of Delivery", "Device/IP Linkage", ...] asserts_delivery_confirmed: Optional[bool] = None # None = omitted, not asserted false asserts_auth_match: Optional[bool] = None asserts_device_match: Optional[bool] = None # Python guardrail — runs after every LLM response if packet.asserts_delivery_confirmed and not evidence.delivery_confirmed: packet.asserts_delivery_confirmed = None # omit — never flip to False
📐
Structured-In / Structured-Out
The LLM receives a typed DisputeEvidence object and must fill a DefensePacket with specific flags. It cannot write free-form prose, narrative, or embellishments.
🔀
Optional[bool] Tri-State
True = confirmed. None = omitted. False = confirmed false from evidence — never set by LLM default. Unverified claims disappear, never get asserted as false.
🧪
Anti-Leakage Evaluation
12% random label-flip noise prevents trivial 99% accuracy. A pure confounder feature (zero correlation) ranks last in LightGBM gain — confirming the model learns real patterns.
